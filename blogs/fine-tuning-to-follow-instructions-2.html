With the InstructionDataset class and custom collate logic established, we instantiate the PyTorch data loaders. These structures automatically shuffle and organize the batches required for the instruction fine-tuning process.

Key Takeaways

  • Instruction datasets integrate into standard data loaders using specialized collate functions to orchestrate dynamic sequence padding and target masking.
  • Base pretrained models fail zero-shot instruction tasks, underscoring the absolute necessity of supervised instructional formatting.
  • Automated conversational benchmarks, leveraging an auxiliary model as an evaluator, offer a scalable and quantifiable mechanism for assessing generative quality over large test sets.

Instruction fine-tuning does not yield simple categorical correctness percentages like classification tasks. Evaluating conversational models utilizes multiple methodologies: - Standardized multi-choice evaluation (e.g., MMLU). - Human preference evaluation frameworks (e.g., LMSYS Chatbot Arena). - Automated LLM-as-a-judge algorithmic evaluations.

To perform a scalable evaluation, we extract responses for the entire test set and serialize them to a JSON file.

import json
from tqdm import tqdm

for i, entry in tqdm(enumerate(test_data), total=len(test_data)):
    input_text = format_input(entry)
    token_ids = generate(
        model=model,
        idx=text_to_token_ids(input_text, tokenizer).to(device),
        max_new_tokens=256,
        context_size=GPT_CONFIG["context_length"],
        eos_id=50256
    )
    generated_text = token_ids_to_text(token_ids, tokenizer)

    response_text = (
        generated_text[len(input_text):]
        .replace("### Response:", "")
        .strip()
    )
    test_data[i]["model_response"] = response_text

with open("instruction-data-with-response.json", "w") as file:
    json.dump(test_data, file, indent=4)

Evaluating the fine-tuned LLM

We execute an automated LLM-as-a-judge evaluation utilizing a local Llama 3 model hosted via Ollama REST API. This secondary model scores the generative output of our fine-tuned network.

import urllib.request

def query_model(prompt, model="llama3", url="http://localhost:11434/api/chat"):
    data = {
        "model": model,
        "messages": [
            {"role": "user", "content": prompt}
        ],
        "options": {
            "seed": 123,
            "temperature": 0,
            "num_ctx": 2048
        }
    }

    payload = json.dumps(data).encode("utf-8")
    request = urllib.request.Request(
        url,
        data=payload,
        method="POST"
    )
    request.add_header("Content-Type", "application/json")

    response_data = ""
    with urllib.request.urlopen(request) as response:
        while True:
            line = response.readline().decode("utf-8")
            if not line:
                break
            response_json = json.loads(line)
            response_data += response_json["message"]["content"]

    return response_data

We define an iterative metric function that prompts the evaluator model to score each local response on a deterministic 100-point integer scale.

def generate_model_scores(json_data, json_key, model="llama3"):
    scores = []
    for entry in tqdm(json_data, desc="Scoring entries"):
        prompt = (
            f"Given the input `{format_input(entry)}` "
            f"and correct output `{entry['output']}`, "
            f"score the model response `{entry[json_key]}`"
            f" on a scale from 0 to 100, where 100 is the best score. "
            f"Respond with the integer number only."
        )
        score = query_model(prompt, model)
        try:
            scores.append(int(score))
        except ValueError:
            print(f"Could not convert score: {score}")
            continue

    return scores

We execute this algorithmic scoring across the aggregate test array.

scores = generate_model_scores(test_data, "model_response")
print(f"Number of scores: {len(scores)} of {len(test_data)}")
print(f"Average score: {sum(scores)/len(scores):.2f}\n")
