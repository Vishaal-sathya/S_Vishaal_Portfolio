We now implement the code required for pretraining the model architecture. We construct a straightforward training loop to repeatedly update the network weights and minimize the cross-entropy loss.

Key Takeaways

  • The training loop systematically calculates loss, computes gradients, and updates model weights over specified epochs while monitoring validation loss.
  • Temperature scaling modifies the softmax distribution, and top-k sampling restricts selection to the most probable tokens, optimizing the balance between generation diversity and coherence.
  • Saving both the model and optimizer state dictionaries ensures that pretraining can be resumed without disrupting adaptive learning rate mechanisms like those in AdamW.

Training an LLM

The pretraining process involves iterating over the dataset to optimize the model parameters.

A typical training loop for training deep neural networks in PyTorch consists of numerous steps, iterating over the batches in the training set for several epochs. In each loop, we calculate the loss for each training set batch to determine loss gradients, which we use to update the model weights so that the training set loss is minimized.

We implement this training flow using the train_model_simple function.

import torch

def train_model_simple(model, train_loader, val_loader, optimizer, device, num_epochs, eval_freq, eval_iter, start_context, tokenizer):
    train_losses, val_losses, track_tokens_seen = [], [], []
    tokens_seen, global_step = 0, -1

    for epoch in range(num_epochs):
        model.train()
        for input_batch, target_batch in train_loader:
            optimizer.zero_grad()
            # Assume calc_loss_batch is defined in the previous section
            loss = calc_loss_batch(
                input_batch, target_batch, model, device
            )
            loss.backward()
            optimizer.step()

            tokens_seen = input_batch.numel()
            global_step += 1

            if global_step % eval_freq == 0:
                train_loss, val_loss = evaluate_model(
                    model, train_loader, val_loader, device, eval_iter
                )
                train_losses.append(train_loss)
                val_losses.append(val_loss)
                track_tokens_seen.append(tokens_seen)

                print(f"Ep {epoch+1} (Step {global_step:06d}): "
                      f"Train loss {train_loss:.3f}, "
                      f"Val loss {val_loss:.3f}"
                 )

        generate_and_print_sample(
            model, tokenizer, device, start_context
        )

    return train_losses, val_losses, track_tokens_seen

The train_model_simple function relies on two auxiliary functions: evaluate_model and generate_and_print_sample.

The evaluate_model function calculates the loss over the training and validation sets while ensuring the model is strictly in evaluation mode. This disables gradient tracking and dropout during the evaluation phase.

# Assume calc_loss_loader is defined in the previous section
def evaluate_model(model, train_loader, val_loader, device, eval_iter):
    model.eval()
    with torch.no_grad():
        train_loss = calc_loss_loader(
            train_loader, model, device, num_batches=eval_iter
        )
        val_loss = calc_loss_loader(
            val_loader, model, device, num_batches=eval_iter
        )
    model.train()
    return train_loss, val_loss

The generate_and_print_sample function tracks whether the generated text improves during the training process. It takes a starting context, converts it into token IDs, and generates a text sample using the generate_text_simple function introduced previously.

def generate_and_print_sample(model, tokenizer, device, start_context):
    model.eval()
    context_size = model.pos_emb.weight.shape[0]
    # Assume text_to_token_ids and token_ids_to_text are defined
    encoded = text_to_token_ids(start_context, tokenizer).to(device)

    with torch.no_grad():
        token_ids = generate_text_simple(
            model=model, idx=encoded,
            max_new_tokens=50, context_size=context_size
        )

    decoded_text = token_ids_to_text(token_ids, tokenizer)
    print(decoded_text.replace("\n", " "))
    model.train()

Because greedy decoding always selects the token with the highest probability score, the model outputs the exact same sequence every time the function runs on the same context.

Temperature scaling

Temperature scaling adds a probabilistic selection process to next-token generation. We replace the deterministic argmax function with a mathematical sampling process. We demonstrate this using a highly restricted vocabulary.

vocab = {
    "closer": 0,
    "every": 1,
    "effort": 2,
    "forward": 3,
    "inches": 4,
    "moves": 5,
    "pizza": 6,
    "toward": 7,
    "you": 8,
}
inverse_vocab = {v: k for k, v in vocab.items()}

Assume the model is given the start context "every effort moves you" and generates the following next-token logits.

next_token_logits = torch.tensor(
    [4.51, 0.89, -1.90, 6.75, 1.63, -1.62, -1.89, 6.28, 1.79]
)

In standard greedy decoding, we convert the logits into probabilities via the softmax function and obtain the token ID corresponding to the generated token using the argmax function.

probas = torch.softmax(next_token_logits, dim=0)
next_token_id = torch.argmax(probas).item()
print(inverse_vocab[next_token_id])

# Output
forward

Since the largest logit value is in index position 3, the generated word is "forward". To implement probabilistic sampling, we replace argmax with the multinomial function.

torch.manual_seed(123)
next_token_id = torch.multinomial(probas, num_samples=1).item()
print(inverse_vocab[next_token_id])

# Output
forward

The multinomial function samples the next token proportional to its probability score. The token "forward" remains the most likely and is selected most frequently. We implement a loop to repeat this sampling 1,000 times to observe the distribution.

def print_sampled_tokens(probas):
    torch.manual_seed(123)
    sample = [torch.multinomial(probas, num_samples=1).item() for i in range(1_000)]
    sampled_ids = torch.bincount(torch.tensor(sample))

    for i, freq in enumerate(sampled_ids):
        print(f"{freq} x {inverse_vocab[i]}")

print_sampled_tokens(probas)

# Output
73 x closer
0 x every
0 x effort
582 x forward
2 x inches
0 x moves
0 x pizza
343 x toward

The word "forward" is sampled most frequently (582 out of 1,000 times), but alternative tokens like "closer" and "toward" are also drawn. We control this distribution via temperature scaling by dividing the logits by a scalar value prior to the softmax transformation.

def softmax_with_temperature(logits, temperature):
    scaled_logits = logits / temperature
    return torch.softmax(scaled_logits, dim=0)

Temperatures greater than 1.0 yield more uniformly distributed token probabilities. Temperatures smaller than 1.0 yield sharper, more confident distributions.

Comparison of probability distributions across different temperature scalings. A lower temperature amplifies the highest probabilities, while a higher temperature spreads probability mass more evenly across the vocabulary.

Top-k sampling

Higher temperature values result in more diverse outputs, but they also increase the probability of sampling grammatically incorrect or nonsensical tokens, such as the word "pizza" in this context. Top-k sampling addresses this by restricting the sampled tokens to the top-k most likely tokens, explicitly excluding all other tokens by masking their probability scores with negative infinity.

Using top-k sampling with k = 3, we focus on the three tokens associated with the highest logits and mask out all other tokens with negative infinity before applying the softmax function.

top_k = 3
top_logits, top_pos = torch.topk(next_token_logits, top_k)

print("Top logits:", top_logits)
print("Top positions:", top_pos)

new_logits = torch.where(
    condition=next_token_logits < top_logits[-1],
    input=torch.tensor(float('-inf')),
    other=next_token_logits
)

topk_probas = torch.softmax(new_logits, dim=0)
print(topk_probas)

# Output
Top logits: tensor([6.7500, 6.2800, 4.5100])
Top positions: tensor([3, 7, 0])
tensor([0.0615, 0.0000, 0.0000, 0.5775, 0.0000, 0.0000, 0.0000, 0.3610, 0.0000])

We combine temperature sampling and top-k sampling to modify the initial generation function, creating a robust generate function.

def generate(model, idx, max_new_tokens, context_size, temperature=0.0, top_k=None, eos_id=None):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -context_size:]
        with torch.no_grad():
            logits = model(idx_cond)
        logits = logits[:, -1, :]

        if top_k is not None:
            top_logits, _ = torch.topk(logits, top_k)
            min_val = top_logits[:, -1]
            logits = torch.where(
                logits < min_val, 
                torch.tensor(float('-inf')).to(logits.device), 
                logits
            )

        if temperature > 0.0:
            logits = logits / temperature
            probs = torch.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
        else:
            idx_next = torch.argmax(logits, dim=-1, keepdim=True)

        if idx_next == eos_id:
            break

        idx = torch.cat((idx, idx_next), dim=1)

    return idx

Saving and loading model state

Pretraining models requires significant computational investment. Saving the model state to disk ensures we do not have to rerun the training loop in new sessions. The standard approach relies on saving the state_dict, a dictionary that maps each layer to its respective parameter tensors.

torch.save(model.state_dict(), 'model.pth')

After saving the weights, we can load them into a newly instantiated model object.

# Assume GPT_CONFIG_124M is defined
model = GPTModel(GPT_CONFIG_124M)
model.load_state_dict(torch.load("model.pth", map_location=device))
model.eval()

If we plan to continue pretraining later, we must also save the optimizer state. Adaptive optimizers, such as AdamW, track historical momentum and variance statistics for every model parameter. If the optimizer state is lost, these statistics are reset, resulting in suboptimal learning dynamics or failure to converge.

We save both the model and optimizer states in a single checkpoint dictionary.

torch.save({
    'model_state_dict': model.state_dict(),
    'optimizer_state_dict': optimizer.state_dict()
}, 'model_and_optimizer.pth')

We restore the exact execution state by loading both components.

checkpoint = torch.load('model_and_optimizer.pth', map_location=device)

model = GPTModel(GPT_CONFIG_124M)
model.load_state_dict(checkpoint['model_state_dict'])

optimizer = torch.optim.AdamW(model.parameters(), lr=5e-4, weight_decay=0.1)
optimizer.load_state_dict(checkpoint['optimizer_state_dict'])

model.train()
