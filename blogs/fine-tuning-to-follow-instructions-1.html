Previously, we implemented the large language model architecture, carried out pretraining, and imported pretrained weights. We then focused on fine-tuning the model for a specific discriminative task by distinguishing between spam and non-spam text messages. We now implement the process for fine-tuning a model to follow explicit human instructions.

Key Takeaways

  • Instruction fine-tuning utilizes structured prompt templates to condition the model on explicit generative tasks rather than predefined categorical labels.
  • Custom collate functions dynamically pad variable-length sequences to the maximum length within a specific batch, optimizing memory usage compared to global dataset padding.
  • Replacing padding token IDs with a specific ignore index (e.g., -100) in the target tensor ensures they do not contribute to the cross-entropy loss computation.

Examples of instructions that are processed by a large language model to generate desired responses.

Preparing a dataset for supervised instruction fine-tuning

We acquire and format the instruction dataset required for fine-tuning a pretrained model. We retrieve the dataset using a programmatic download function.

import json
import os
import urllib.request

def download_and_load_file(file_path, url):
    if not os.path.exists(file_path):
        with urllib.request.urlopen(url) as response:
            text_data = response.read().decode("utf-8")
        with open(file_path, "w", encoding="utf-8") as file:
            file.write(text_data)
    else:
        with open(file_path, "r", encoding="utf-8") as file:
            text_data = file.read()

    with open(file_path, "r") as file:
        data = json.load(file)
    return data

Instruction fine-tuning involves training a model on a dataset where explicit input-target pairs are provided. Various structural conventions exist to format these entries for model ingestion.

Comparison of prompt styles for instruction fine-tuning in language models. The Alpaca style (left) uses a structured format with defined sections for instruction, input, and response, while the Phi-3 style (right) employs a simpler format with designated `<|user|>` and `<|assistant|>` tokens.

We define a format_input function to convert the entries from the raw dictionary into the structured Alpaca-style input format.

def format_input(entry):
    instruction_text = (
        f"Below is an instruction that describes a task. "
        f"Write a response that appropriately completes the request."
        f"\n\n### Instruction:\n{entry['instruction']}"
    )

    input_text = (
        f"\n\n### Input:\n{entry['input']}" if entry["input"] else ""
    )
    return instruction_text + input_text

Organizing data into training batches

The batching process for instruction data requires sequential processing steps to handle variable sequence lengths.

The five substeps involved in implementing the batching process. (2.1) Applying the prompt template. (2.2) Using tokenization. (2.3) Adding padding tokens. (2.4) Creating target token IDs. (2.5) Replacing -100 placeholder tokens to mask padding tokens in the loss function.

We define a custom PyTorch Dataset class to encode the full text sequences containing the instructions, inputs, and desired responses.

import torch
from torch.utils.data import Dataset

class InstructionDataset(Dataset):
    def __init__(self, data, tokenizer):
        self.data = data
        self.encoded_texts = []

        for entry in data:
            instruction_plus_input = format_input(entry)
            response_text = f"\n\n### Response:\n{entry['output']}"
            full_text = instruction_plus_input + response_text
            self.encoded_texts.append(
                tokenizer.encode(full_text)
            )

    def __getitem__(self, index):
        return self.encoded_texts[index]

    def __len__(self):
        return len(self.data)

We develop a custom collate function which pads the training examples in each batch to a uniform length. This specific approach minimizes unnecessary computational overhead by extending sequences only to match the longest element within the current batch, rather than padding against the entire dataset maximum.

def custom_collate_draft_1(batch, pad_token_id=50256, device="cpu"):
    batch_max_length = max(len(item)+1 for item in batch)
    inputs_lst = []

    for item in batch:
        new_item = item.copy()
        new_item += [pad_token_id]
        padded = (
            new_item + [pad_token_id] *
            (batch_max_length - len(new_item))
        )
        inputs = torch.tensor(padded[:-1])
        inputs_lst.append(inputs)

    inputs_tensor = torch.stack(inputs_lst).to(device)
    return inputs_tensor

We must structure the batches with the target token IDs corresponding to the input token IDs. The target token IDs match the input token IDs but are shifted precisely one position to the right to facilitate causal language modeling.

def custom_collate_draft_2(batch, pad_token_id=50256, device="cpu"):
    batch_max_length = max(len(item)+1 for item in batch)
    inputs_lst, targets_lst = [], []

    for item in batch:
        new_item = item.copy()
        new_item += [pad_token_id]
        padded = (
            new_item + [pad_token_id] *
            (batch_max_length - len(new_item))
        )
        inputs = torch.tensor(padded[:-1])
        targets = torch.tensor(padded[1:])
        inputs_lst.append(inputs)
        targets_lst.append(targets)

    inputs_tensor = torch.stack(inputs_lst).to(device)
    targets_tensor = torch.stack(targets_lst).to(device)
    return inputs_tensor, targets_tensor

We assign a -100 placeholder value to all padding tokens within the target tensors. This special value dictates that these tokens are excluded from the training loss calculation. We retain exactly one end-of-text token (ID 50256) in the target list to ensure the model learns to generate termination tokens.

We implement the final custom_collate_fn containing the masking logic.

def custom_collate_fn(
    batch, pad_token_id=50256, ignore_index=-100, allowed_max_length=1024, device="cpu"
):
    batch_max_length = max(len(item)+1 for item in batch)
    inputs_lst, targets_lst = [], []

    for item in batch:
        new_item = item.copy()
        new_item += [pad_token_id]
        padded = (
            new_item + [pad_token_id] *
            (batch_max_length - len(new_item))
        )

        inputs = torch.tensor(padded[:-1])
        targets = torch.tensor(padded[1:])
        mask = targets == pad_token_id
        indices = torch.nonzero(mask).squeeze()

        if indices.numel() > 1:
            targets[indices[1:]] = ignore_index

        if allowed_max_length is not None:
            inputs = inputs[:allowed_max_length]
            targets = targets[:allowed_max_length]

        inputs_lst.append(inputs)
        targets_lst.append(targets)

    inputs_tensor = torch.stack(inputs_lst).to(device)
    targets_tensor = torch.stack(targets_lst).to(device)
    return inputs_tensor, targets_tensor

inputs, targets = custom_collate_fn(batch)
print("Inputs:\n", inputs)
print("Targets:\n", targets)

The underlying mathematical logic behind replacing target tokens with -100 relates directly to the cross-entropy function. We demonstrate this using a simplified synthetic example computing the loss when the model predicts a sequence.

logits_1 = torch.tensor([
    [-1.0, 1.0],
    [-0.5, 1.5]
])
targets_1 = torch.tensor([0, 1]) 
loss_1 = torch.nn.functional.cross_entropy(logits_1, targets_1)
print(loss_1)

# Output
tensor(1.1269)

If we evaluate a sequence containing an arbitrary third token, the loss shifts.

logits_2 = torch.tensor([
    [-1.0, 1.0],
    [-0.5, 1.5],
    [-0.5, 1.5]
])
targets_2 = torch.tensor([0, 1, 1])
loss_2 = torch.nn.functional.cross_entropy(logits_2, targets_2)
print(loss_2)

# Output
tensor(0.7936)

If we replace the third target token ID with the ignore index (-100), the function excludes that index entirely.

targets_3 = torch.tensor([0, 1, -100])
loss_3 = torch.nn.functional.cross_entropy(logits_2, targets_3)
print(loss_3)
print("loss_1 == loss_3:", loss_1 == loss_3)

# Output
tensor(1.1269)
loss_1 == loss_3: tensor(True)

The resulting loss precisely matches the initial two-element sequence. The default behavior of the PyTorch function is cross_entropy(..., ignore_index=-100). We leverage this parameter to exclude arbitrary padding tokens inserted to equalize batch dimensions.

IMPORTANT

In addition to masking out padding tokens, it is standard practice to mask out the target token IDs corresponding to the prompt instruction itself. By masking the instruction segments, the cross-entropy loss is computed exclusively for the generated response target IDs. The model optimizes strictly for generating accurate responses rather than dedicating capacity to memorizing the static prompt templates.
