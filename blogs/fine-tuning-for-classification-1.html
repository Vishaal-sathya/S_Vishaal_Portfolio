We have established the large language model architecture, executed pretraining, and imported pretrained weights. We now focus on fine-tuning the model for a specific discriminative task: classifying text messages as either spam or non-spam.

Key Takeaways

  • Classification fine-tuning restricts a model to predicting a predefined set of categorical labels, contrasting with open-ended instruction fine-tuning.
  • Severely imbalanced datasets require structural adjustment, such as undersampling the majority class, to prevent model bias during optimization.
  • Variable-length text sequences must be padded to a uniform length to enable parallel processing within PyTorch tensor structures.

Different categories of fine-tuning

The most prominent methodologies for adapting language models to target applications are instruction fine-tuning and classification fine-tuning. Instruction fine-tuning involves training a language model on a curated set of tasks using specific instructions. This improves its ability to comprehend and execute requests described in natural language prompts.

Two different instruction fine-tuning scenarios. At the top, the model is tasked with determining whether a given text is spam. At the bottom, the model receives an instruction detailing how to translate an English sentence into German.

In classification fine-tuning, the model is trained strictly to recognize a specific, closed set of class labels. A model that is fine-tuned for classification is restricted mathematically to outputting probabilities for the classes it encountered during its training.

A text classification scenario using a large language model. A model fine-tuned for spam classification does not require further natural language instruction alongside the input string. In contrast to an instruction fine-tuned model, it is restricted to responding with a predefined label.

Preparing the dataset

We begin by acquiring the raw data. We download the UCI SMS Spam Collection dataset directly via a script and extract its contents.

import urllib.request
import zipfile
import os
from pathlib import Path

url = "https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip"
zip_path = "sms_spam_collection.zip"
extracted_path = "sms_spam_collection"
data_file_path = Path(extracted_path) / "SMSSpamCollection.tsv"

def download_and_unzip_spam_data(
    url, zip_path, extracted_path, data_file_path
):
    if data_file_path.exists():
        print(f"{data_file_path} already exists. Skipping download and extraction.")
        return

    with urllib.request.urlopen(url) as response:
        with open(zip_path, "wb") as out_file:
            out_file.write(response.read())

    with zipfile.ZipFile(zip_path, "r") as zip_ref:
        zip_ref.extractall(extracted_path)

    original_file_path = Path(extracted_path) / "SMSSpamCollection"
    os.rename(original_file_path, data_file_path)
    print(f"File downloaded and saved as {data_file_path}")

download_and_unzip_spam_data(url, zip_path, extracted_path, data_file_path)

The dataset is formatted as a tab-separated text file. We load the raw data into a pandas DataFrame.

import pandas as pd

df = pd.read_csv(
    data_file_path, sep="\t", header=None, names=["Label", "Text"]
)

We inspect the class label distribution to evaluate the structural balance of the dataset.

print(df["Label"].value_counts())

The data contains the "ham" class (non-spam) at a significantly higher frequency than the "spam" class. To prevent the model from developing a bias toward the majority class, and to reduce the overall dataset size for faster iteration, we undersample the dataset. We extract exactly 747 instances from the "ham" class to match the "spam" class.

def create_balanced_dataset(df):
    num_spam = df[df["Label"] == "spam"].shape[0]
    ham_subset = df[df["Label"] == "ham"].sample(
        num_spam, random_state=123
    )
    balanced_df = pd.concat([
        ham_subset, df[df["Label"] == "spam"]
    ])
    return balanced_df

balanced_df = create_balanced_dataset(df)
balanced_df["Label"] = balanced_df["Label"].map({"ham": 0, "spam": 1})

print(balanced_df["Label"].value_counts())

# Output
Label
0    747
1    747
Name: count, dtype: int64

The function maps the string class labels "ham" and "spam" into the integer class labels 0 and 1, respectively. The resulting dataset is perfectly balanced.

We implement a random_split function to partition the dataset into three independent subsets: 70 percent for training, 10 percent for validation, and 20 percent for testing.

def random_split(df, train_frac, validation_frac):
    df = df.sample(
        frac=1, random_state=123
    ).reset_index(drop=True)

    train_end = int(len(df) * train_frac)
    validation_end = train_end + int(len(df) * validation_frac)

    train_df = df[:train_end]
    validation_df = df[train_end:validation_end]
    test_df = df[validation_end:]

    return train_df, validation_df, test_df

train_df, validation_df, test_df = random_split(balanced_df, 0.7, 0.1)

We persist the split datasets to disk as CSV files to ensure consistent access during the data loading phase.

train_df.to_csv("train.csv", index=None)
validation_df.to_csv("validation.csv", index=None)
test_df.to_csv("test.csv", index=None)

Creating data loaders

During the pretraining phase, we utilized a sliding window technique to generate uniformly sized text chunks. However, the spam dataset contains distinct text messages of varying lengths. To assemble these messages into discrete tensors, we face two primary options: 1. Truncate all messages to the length of the shortest message in the batch. 2. Pad all messages to the length of the longest message in the batch.

The first option is computationally cheaper but results in unacceptable information loss when shorter messages deviate significantly from the maximum length. Therefore, we implement the padding approach. We pad shorter sequences by appending the token ID corresponding to the <|endoftext|> token.

import tiktoken

tokenizer = tiktoken.get_encoding("gpt2")
print(tokenizer.encode("<|endoftext|>", allowed_special={"<|endoftext|>"}))

# Output
[50256]

The input text preparation process. First, each input text message is converted into a sequence of token IDs. To ensure uniform sequence lengths, shorter sequences are padded with the token ID 50256 to precisely match the length of the longest sequence.

We define the SpamDataset class to manage this process automatically. The class identifies the longest sequence within its dataset split, encodes the text messages, and appends the padding token to ensure all sequences conform to the maximum length.

import torch
from torch.utils.data import Dataset

class SpamDataset(Dataset):
    def __init__(self, csv_file, tokenizer, max_length=None, pad_token=50256):
        self.data = pd.read_csv(csv_file)
        self.encoded_texts = [tokenizer.encode(text) for text in self.data['Text']]

        if max_length is None:
            self.max_length = self._longest_encoded_length()
        else:
            self.max_length = max_length
            self.encoded_texts = [
                encoded_text[:self.max_length] 
                for encoded_text in self.encoded_texts
            ]

        self.encoded_texts = [
            encoded_text + [pad_token] * (self.max_length - len(encoded_text))
            for encoded_text in self.encoded_texts
        ]

    def __getitem__(self, index):
        encoded = self.encoded_texts[index]
        label = self.data.iloc[index]['Label']
        return (
            torch.tensor(encoded, dtype=torch.long),
            torch.tensor(label, dtype=torch.long)
        )

    def __len__(self):
        return len(self.data)

    def _longest_encoded_length(self):
        max_length = 0
        for encoded_text in self.encoded_texts:
            encoded_length = len(encoded_text)
            if encoded_length > max_length:
                max_length = encoded_length
        return max_length

We instantiate the datasets for the training, validation, and test splits. The validation and test datasets explicitly inherit the maximum sequence length computed from the training dataset to maintain dimensional consistency.

train_dataset = SpamDataset(
    csv_file="train.csv",
    max_length=None,
    tokenizer=tokenizer
)

val_dataset = SpamDataset(
    csv_file="validation.csv",
    max_length=train_dataset.max_length,
    tokenizer=tokenizer
)

test_dataset = SpamDataset(
    csv_file="test.csv",
    max_length=train_dataset.max_length,
    tokenizer=tokenizer
)

We wrap these dataset objects in PyTorch DataLoader instances, which shuffle the training data and construct standardized batches of 8 samples each.

from torch.utils.data import DataLoader

num_workers = 0
batch_size = 8
torch.manual_seed(123)

train_loader = DataLoader(
    dataset=train_dataset,
    batch_size=batch_size,
    shuffle=True,
    num_workers=num_workers,
    drop_last=True,
)

val_loader = DataLoader(
    dataset=val_dataset,
    batch_size=batch_size,
    num_workers=num_workers,
    drop_last=False,
)

test_loader = DataLoader(
    dataset=test_dataset,
    batch_size=batch_size,
    num_workers=num_workers,
    drop_last=False,
)

print(f"{len(train_loader)} training batches")
print(f"{len(val_loader)} validation batches")
print(f"{len(test_loader)} test batches")

# Output
130 training batches
19 validation batches
38 test batches

With the data loaders established, the input pipeline is fully prepared. The next phase involves configuring the neural network architecture to process these classification targets.
