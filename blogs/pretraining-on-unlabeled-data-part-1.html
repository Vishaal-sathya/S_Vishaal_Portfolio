We now configure the large language model and review the text generation process established in the previous section. We adjust the configuration to facilitate training on standard hardware.

Key Takeaways

  • Cross-entropy loss measures the performance of generated text by comparing the model's predicted probability distributions to the actual target tokens.
  • Perplexity provides an interpretable evaluation metric derived directly from the exponential of the cross-entropy loss.
  • Evaluating the untrained model on training and validation datasets establishes a baseline loss before initiating the pretraining process.

Model initialization and utility functions

We initialize the model using a configuration dictionary. The primary adjustment compared to the previous architectural configuration is a reduction in the context length from 1024 to 256 tokens. This modification reduces the computational memory demands of training the model, making it possible to execute the training process on a standard workstation.

import torch
from chapter04 import GPTModel

GPT_CONFIG_124M = {
    "vocab_size": 50257,
    "context_length": 256,
    "emb_dim": 768,
    "n_heads": 12,
    "n_layers": 12,
    "drop_rate": 0.1,
    "qkv_bias": False
}

torch.manual_seed(123)
model = GPTModel(GPT_CONFIG_124M)
model.eval()

We introduce two utility functions, text_to_token_ids and token_ids_to_text, which facilitate the conversion between human-readable text and numerical token representations.

Generating text involves encoding text into token IDs that the LLM processes into logit vectors. The logit vectors are then converted back into token IDs and detokenized into a text representation.

def text_to_token_ids(text, tokenizer):
    encoded = tokenizer.encode(text, allowed_special={'<|endoftext|>'})
    encoded_tensor = torch.tensor(encoded).unsqueeze(0)
    return encoded_tensor

def token_ids_to_text(token_ids, tokenizer):
    flat = token_ids.squeeze(0)
    return tokenizer.decode(flat.tolist())

We test these functions by generating text with our untrained model.

import tiktoken
from chapter04 import generate_text_simple

start_context = "Every effort moves you"
tokenizer = tiktoken.get_encoding("gpt2")

token_ids = generate_text_simple(
    model=model,
    idx=text_to_token_ids(start_context, tokenizer),
    max_new_tokens=10,
    context_size=GPT_CONFIG_124M["context_length"]
)

print("Output text:\n", token_ids_to_text(token_ids, tokenizer))

# Output

The model outputs incoherent text because it has not yet undergone training. To define what makes text coherent and to optimize the network weights, we must implement a numerical method to evaluate the generated content. We calculate a loss metric for the generated outputs, which serves as a progress and success indicator during the training phase.

Calculating the text generation loss

We define two input examples and their corresponding targets to illustrate the loss calculation.

inputs = torch.tensor([
    [16833, 3626, 6100], # ["every effort moves",
    [40, 1107, 588]      #  "I really like"]
])

targets = torch.tensor([
    [3626, 6100, 345 ],  # [" effort moves you",
    [1107, 588, 11311]   #  " really like chocolate"]
])

We feed the inputs into the model to calculate the logit vectors for the two input examples, each comprising three tokens. We apply the softmax function to transform these logits into probability scores, and then apply the argmax function to obtain the corresponding predicted token IDs.

with torch.no_grad():
    logits = model(inputs)

probas = torch.softmax(logits, dim=-1)
token_ids = torch.argmax(probas, dim=-1, keepdim=True)
print("Token IDs:\n", token_ids)

# Output
Token IDs:
 tensor([[[16657],
         [13866],
         [44376]],

        [[49906],
         [29669],
         [ 6972]]])

We convert the predicted token IDs back into text to compare them against the target tokens.

print(f"Targets batch 1: {token_ids_to_text(targets[0], tokenizer)}")
print(f"Outputs batch 1: {token_ids_to_text(token_ids[0].flatten(), tokenizer)}")

# Output
Targets batch 1:  effort moves you
Outputs batch 1:  Armedbage inaction

The output tokens differ significantly from the target tokens we want the model to generate. We evaluate the performance of the generated text numerically via a loss function. This metric drives the training process by increasing the softmax probability in the index positions corresponding to the correct target token IDs.

We print the initial softmax probability scores corresponding to the target tokens for each input text.

text_idx = 0
target_probas_1 = probas[text_idx, [0, 1, 2], targets[text_idx]]
print("Text 1:", target_probas_1)

text_idx = 1
target_probas_2 = probas[text_idx, [0, 1, 2], targets[text_idx]]
print("Text 2:", target_probas_2)

# Output
Text 1: tensor([7.4541e-05, 3.1295e-05, 1.2549e-05])
Text 2: tensor([1.0337e-05, 5.4610e-05, 5.2052e-06])

We apply the logarithm to the probability scores. Working with logarithms of probabilities is numerically more stable and manageable in mathematical optimization than handling the raw fractional scores directly.

log_probas = torch.log(torch.cat((target_probas_1, target_probas_2)))
print(log_probas)

# Output
tensor([ -9.5042, -10.3720, -11.2859, -11.4798,  -9.8153, -12.1658])

We combine these log probabilities into a single score by computing their average. The optimization objective is to push this average log probability as close to 0 as possible by updating the model's weights. In deep learning, standard practice minimizes the negative average log probability, which is the average log probability multiplied by -1.

avg_log_probas = torch.mean(log_probas)
neg_avg_log_probas = avg_log_probas * -1
print(neg_avg_log_probas)

# Output
tensor(10.7705)

In deep learning nomenclature, this metric is known as the cross-entropy loss. PyTorch includes a built-in cross_entropy function that computes these sequential steps automatically.

Calculating the loss involves several steps. Steps 1 to 3 calculate the token probabilities corresponding to the target tensors. These probabilities are then transformed via a logarithm and averaged in steps 4 to 6.

We verify the shape of the logits and target tensors prior to applying the built-in function.

print("Logits shape:", logits.shape)
print("Targets shape:", targets.shape)

# Output
Logits shape: torch.Size([2, 3, 50257])
Targets shape: torch.Size([2, 3])

The logits tensor has three dimensions: batch size, sequence length, and vocabulary size. The targets tensor has two dimensions: batch size and sequence length. We flatten these tensors over the batch dimension to align with the expected input signature of PyTorch's cross_entropy function.

logits_flat = logits.flatten(0, 1)
targets_flat = targets.flatten()

print("Flattened logits:", logits_flat.shape)
print("Flattened targets:", targets_flat.shape)

# Output
Flattened logits: torch.Size([6, 50257])
Flattened targets: torch.Size([6])

The targets_flat tensor contains the exact token IDs we want the network to generate, and logits_flat contains the unscaled network outputs. The cross_entropy function handles the softmax application, target selection, logarithmic transformation, and averaging internally.

loss = torch.nn.functional.cross_entropy(logits_flat, targets_flat)
print(loss)

# Output
tensor(10.7705)

Perplexity Perplexity is a measure often used alongside cross-entropy loss to evaluate the performance of language models. It provides an interpretable way to understand the uncertainty of a model in predicting the next token in a sequence. Perplexity measures how well the probability distribution predicted by the model matches the actual distribution of the words in the dataset. Similar to the loss, a lower perplexity indicates that model predictions are closer to the actual distribution.

Perplexity is calculated mathematically as torch.exp(loss). It is often considered more interpretable than the raw loss value because it signifies the effective vocabulary size about which the model remains uncertain at each time step.

Calculating the training and validation set losses

We prepare the training and validation datasets to compute the baseline loss. We utilize a small text dataset, "The Verdict", for this demonstration. We divide the dataset into a training split (90 percent) and a validation split (10 percent).

file_path = "the-verdict.txt"
with open(file_path, "r", encoding="utf-8") as file:
    text_data = file.read()

train_ratio = 0.90
split_idx = int(train_ratio * len(text_data))
train_data = text_data[:split_idx]
val_data = text_data[split_idx:]

We instantiate the data loaders to construct discrete batches for model evaluation.

from chapter02 import create_dataloader_v1

train_loader = create_dataloader_v1(
    train_data,
    batch_size=2,
    max_length=GPT_CONFIG_124M["context_length"],
    stride=GPT_CONFIG_124M["context_length"],
    drop_last=True,
    shuffle=True,
    num_workers=0
)

val_loader = create_dataloader_v1(
    val_data,
    batch_size=2,
    max_length=GPT_CONFIG_124M["context_length"],
    stride=GPT_CONFIG_124M["context_length"],
    drop_last=False,
    shuffle=False,
    num_workers=0
)

We implement a utility function to calculate the cross-entropy loss for a single discrete batch.

def calc_loss_batch(input_batch, target_batch, model, device):
    input_batch = input_batch.to(device)
    target_batch = target_batch.to(device)
    logits = model(input_batch)
    loss = torch.nn.functional.cross_entropy(
        logits.flatten(0, 1), target_batch.flatten()
    )
    return loss

We use calc_loss_batch to implement the calc_loss_loader function, which computes the average loss across all batches sampled by a given data loader.

def calc_loss_loader(data_loader, model, device, num_batches=None):
    total_loss = 0.0
    if len(data_loader) == 0:
        return float("nan")
    elif num_batches is None:
        num_batches = len(data_loader)
    else:
        num_batches = min(num_batches, len(data_loader))

    for i, (input_batch, target_batch) in enumerate(data_loader):
        if i < num_batches:
            loss = calc_loss_batch(
                input_batch, target_batch, model, device
            )
            total_loss += loss.item()
        else:
            break

    return total_loss / num_batches

We evaluate this logic by applying the calc_loss_loader function to both the training and validation set loaders.

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

with torch.no_grad():
    train_loss = calc_loss_loader(train_loader, model, device)
    val_loss = calc_loss_loader(val_loader, model, device)

print("Training loss:", train_loss)
print("Validation loss:", val_loss)

# Output
Training loss: 10.98257933722602
Validation loss: 11.021645545959473

The loss values are relatively high because the network parameters have not yet been updated. The loss metric will approach 0 as the model learns to generate the correct subsequent tokens. We will configure the optimization loop and begin pretraining the model on this dataset in the next section.
