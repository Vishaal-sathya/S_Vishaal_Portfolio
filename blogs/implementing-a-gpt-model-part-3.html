Previously, we established a high-level overview of a GPT architecture using the DummyGPTModel with DummyTransformerBlock and DummyLayerNorm classes as placeholders. We now replace the DummyTransformerBlock and DummyLayerNorm placeholders with the fully implemented TransformerBlock and LayerNorm classes to assemble a functional 124-million-parameter version of GPT-2.

Key Takeaways

  • The complete GPT architecture integrates token embeddings, positional embeddings, stacked transformer blocks, layer normalization, and a linear output head.
  • The original GPT-2 model utilizes weight tying between the token embedding and linear output layers to reduce the total parameter count to 124 million.
  • Text generation involves evaluating logits, converting them to probabilities, and sequentially appending the most likely next token to the input context.

Coding the GPT model

We assemble the complete model architecture by instantiating the embedding layers, a sequential container of transformer blocks, the final layer normalization, and the output head.

An overview of the GPT model architecture showing the flow of data through the GPT model. Starting from the bottom, tokenized text is first converted into token embeddings, which are then augmented with positional embeddings. This combined information forms a tensor that is passed through a series of transformer blocks shown in the center (each containing multi-head attention and feed forward neural network layers with dropout and layer normalization), which are stacked on top of each other and repeated 12 times.

import torch
import torch.nn as nn
# TransformerBlock and LayerNorm are defined in previous chapters

class GPTModel(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.tok_emb = nn.Embedding(cfg["vocab_size"], cfg['emb_dim'])
        self.pos_emb = nn.Embedding(cfg["context_length"], cfg["emb_dim"])
        self.drop_emb = nn.Dropout(cfg["drop_rate"])

        self.trf_blocks = nn.Sequential(
            *[TransformerBlock(cfg) for _ in range(cfg["n_layers"])]
        )
        self.final_norm = LayerNorm(cfg['emb_dim'])
        self.out_head = nn.Linear(cfg["emb_dim"], cfg["vocab_size"], bias=False)

    def forward(self, in_idx):
        batch_len, seq_len = in_idx.shape
        tok_embeds = self.tok_emb(in_idx)
        pos_embeds = self.pos_emb(torch.arange(seq_len, device=in_idx.device))
        x = tok_embeds + pos_embeds
        x = self.drop_emb(x)
        x = self.trf_blocks(x)
        x = self.final_norm(x)
        logits = self.out_head(x)

        return logits

The output tensor has the shape [2, 4, 50257] because we passed in two input sequences containing four tokens each. The final dimension, 50257, corresponds directly to the vocabulary size of the tokenizer.

We now analyze the size of the model architecture. Using the numel() method, which stands for "number of elements", we collect the total number of trainable parameters within the model's weight tensors.

total_params = sum(p.numel() for p in model.parameters())
print(f"Total number of parameters: {total_params:,}")

# Output
Total number of parameters: 163,009,536

Although this model targets the 124-million-parameter configuration of GPT-2, the actual count is 163 million. This discrepancy arises from a concept called weight tying, which was utilized in the original GPT-2 architecture. Weight tying means that the model reuses the weights from the token embedding layer in its output layer.

We inspect the shapes of the token embedding layer and the linear output layer to clarify this overlap.

print("Token embedding layer shape:", model.tok_emb.weight.shape) 
print("Output layer shape:", model.out_head.weight.shape)

# Output
Token embedding layer shape: torch.Size([50257, 768])
Output layer shape: torch.Size([50257, 768])

The token embedding and output layers are very large because they contain a row for each of the 50,257 tokens in the vocabulary. We subtract the output layer parameter count from the total model count to account for weight tying.

total_params_gpt2 = (
    total_params - sum(p.numel() for p in model.out_head.parameters())
)
print(
    f"Number of trainable parameters "
    f"considering weight tying: {total_params_gpt2:,}"
)

# Output
Number of trainable parameters considering weight tying: 124,412,160

The parameter count is now approximately 124 million, which strictly matches the original size of the small GPT-2 model.

Weight tying reduces the overall memory footprint and computational complexity of the model. However, modern research indicates that using separate token embedding and output layers often results in better training dynamics and model performance. For this reason, we retain separate layers in our GPTModel implementation, a practice common in contemporary large language models.

Generating text

The process by which a GPT model goes from output tensors to generated text involves several steps. These steps include evaluating the output tensors, selecting tokens based on a probability distribution, and converting these token IDs back into human-readable text.

In each step, the model outputs a matrix where vectors represent potential next tokens. The vector corresponding to the next token is extracted and converted into a probability distribution via the softmax function. Within this distribution, the index of the highest probability value is located. This index translates to the token ID. This token ID is then decoded back into text, producing the next token in the sequence. Finally, this token is appended to the previous inputs, which forms a new input sequence for the subsequent iteration.

The mechanics of text generation in a GPT model by showing a single iteration in the token generation process. The process begins by encoding the input text into token IDs, which are then fed into the GPT model. The outputs of the model are then converted back into text and appended to the original input text.

def generate_text_simple(model, idx, max_new_tokens, context_size):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -context_size:]
        with torch.no_grad():
            logits = model(idx_cond)

        logits = logits[:, -1, :]
        probas = torch.softmax(logits, dim=-1)
        idx_next = torch.argmax(probas, dim=-1, keepdim=True)
        idx = torch.cat((idx, idx_next), dim=1)
    return idx

To implement the generate_text_simple function, we apply a softmax transformation to convert the logits into a probability distribution. We then identify the position with the highest probability value using torch.argmax. The softmax function is strictly monotonic, meaning it preserves the order of its inputs when mapped to outputs. Consequently, the position with the highest score in the softmax output tensor is identical to the position in the logit tensor. We could apply the torch.argmax function to the logits tensor directly and obtain the exact same result. We provide the softmax conversion step here to fully illustrate the theoretical process of transforming logits to probabilities. Selecting the most likely next token using argmax is a strategy known as greedy decoding.

We test the generate_text_simple function using the string "Hello, I am" as the starting context. We first encode this context string into token IDs.
